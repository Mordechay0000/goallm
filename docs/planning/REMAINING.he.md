# מה נשאר כדי שהפרויקט יהיה פעיל

עודכן: 2026-10-16. המסמך מסכם מה תוקן בסבב האחרון, מה חוסם עלייה לאוויר, ואיזה מודל מתאים לסינון התמונות.

---

## 1. מה תוקן בסבב הזה (בקצרה)

| תחום | מה היה | מה עכשיו |
| --- | --- | --- |
| כללי תגיות | כל משתמש רשום יכול לשנות/למחוק כללים **גלובליים** | מנהל בלבד |
| זיהוי IP | `X-Forwarded-For` נלקח מכל לקוח → התחזות לבית אחר וצפייה בגלישה שלו | רק מ-`TRUSTED_PROXY_IPS`, קריאה מימין לשמאל; הפרוקסי **דורס** את הכותרת לפני ה-CRM |
| זהות | רק לפי IP (נשבר ב-CGNAT) | **פרטי התחברות אישיים לפרוקסי** לכל משתמש (עמוד "חיבורים"); IP נשאר כגיבוי |
| העלאות קבצים | כל סיומת (`.html`) מוגשת מדומיין ה-CRM → גניבת טוקן מנהל | רשימה מותרת + `nosniff` + `CSP: sandbox` + `attachment` |
| סרגל גלישה | טוקן מנהל מוזרק לדפים של אתרים זרים | אין טוקן; פעולת מנהל = דף CRM + לחיצת אישור. דף ה-iframe שקיבל פקודות מכל אתר – הוסר |
| הגדרות נעולות | נאכפו רק בממשק | נאכפות בשרת (כולל יצירת פרופיל/תזמון) |
| סודות | `dev-secret`, `change-this…`, `filter:f123456Ab` | נוצרים אקראית ונשמרים ב-`.storage`; אין סיסמת פרוקסי קבועה |
| Fail-closed | שגיאה בבדיקת מדיניות = הבקשה עוברת | שגיאה = חסימה |
| OTP | `random`, בלי מגבלת ניסיונות | `secrets`, 5 ניסיונות לקוד |
| דליפות תמונה | AVIF/HEIC/SVG/GIF מונפש/תמונה מוסווית כ-HTML או gzip עוברים | מזוהים לפי תוכן; אנימציה נבדקת בכמה פריימים; פורמט לא מפוענח = חסום |
| וידאו | עובר חופשי בכל אתר מותר | חסום כברירת מחדל (בשלב הכותרות, בלי לטעון לזיכרון); נפתח לאתר בכלל גלובלי |
| מנתח VLM | מופע llama.cpp אחד ל-16 תהליכונים, WebP נכשל, דליפת זיכרון | נעילה; כל פורמט מומר ל-JPEG; backend לשרת OpenAI-compatible (vLLM) עם JSON schema וסף הסתברות א-סימטרי |
| תמונות "בבדיקה" | נשארות מטושטשות עד רענון ידני | מתחלפות לבד כשהבדיקה מסתיימת |
| ביצועים | ~6 שאילתות SQLite + בניית resolver לכל בקשה, thread + HTTP לכל בקשה | מטמון בזיכרון (מתרענן תוך שנייה משינוי), עיבוד כבד מחוץ ל-event loop, חיבור SQLite לכל thread |
| עקביות | סנכרון CRM→core מחק והכניס מחדש (חלון בלי חסימות); כתב את כל הכללים הגלובליים לכל משתמש כל דקה | טרנזקציה אחת, diff בלבד |
| באגים נוספים | התקנה חדשה איבדה 4 עמודות (`add_policy` נכשל); אתרי windows-1255 חזרו מקודדים לא נכון; תזמון לילה (22:00–06:00) לא עבד; משתמש שנמחק השאיר שיוך IP | תוקנו |

כל זה מכוסה ב-69 בדיקות (`pytest test/ -q`) ונבדק גם בהרצה אמיתית של `mitmdump`.

> תיקון לדוח הקודם שלי: מסנן ה-JSON **לא** מסתיר מפתחות (רק ערכים). מה שכן תוקן: הוא הרכיב מחדש כל תגובת JSON גם כשלא שינה דבר.

## 2. חוסמים – לפני שמשתמש אמיתי גולש

1. **מודל אמיתי.** ברירת המחדל `IMAGE_ANALYZER=simulated` מחזירה תוצאה **אקראית** (לפי hash של הקובץ). בלי `openai`/`llama_cpp` אין סינון תמונות בכלל.
2. **סט זהב + מדידה.** 2,000–5,000 תמונות קשות מתויגות ידנית לפי התקן (אישה קטנה ברקע, יד/שיער בפינה, ציור, תמונה בתוך תמונה, מטושטש, צללית). הרצה: `python -m tools.eval_golden_set <dir>`. יעד: recall ≥ 99.5% על מה שחייב להיחסם. **בלי זה כל בחירת מודל/prompt היא ניחוש.**
3. **החלטות הלכתיות – שלך, לא שלי** (ב-`config/llm/system_prompt.txt`):
   - סעיף 5 הוגדר מחדש: "חשיפה" = כתפיים, זרועות עליונות, חזה, בטן, גב, ירכיים/ברכיים (פנים, צוואר, ידיים ואמות של גבר – לא). הנוסח הקודם ("any visible body exposure") כלל גם פנים, כלומר כל אדם.
   - נוסף כלל "לא בטוח = חסום": מין לא ברור → אישה; גיל לא ברור → 9+.
   - ציורים / מצוירים / AI נחשבים כמו צילום. **לא הוגדר:** בובות, מנקינים, צלליות, פסלים מופשטים.
   - `VLM_YES_THRESHOLD=0.2`: חוסם גם כשהמודל נותן רק 20% ל"כן". נמוך יותר = יותר חסימות-שווא, פחות החמצות.
4. **פריסה:** שרת GPU עם vLLM; `mitmdump` על שרת עם IP קבוע; nginx + TLS ל-CRM; `TRUSTED_PROXY_IPS` (כתובת הפרוקסי וה-reverse proxy); `CRM_PROXY_SECRET` זהה בשני השרתים; `GOALLM_FIRST_USER_ADMIN=0` ואז `python -m crm.manage set-admin <phone>`. כל המשתנים: [`.env.example`](../../.env.example).
5. **רשימה לבנה ראשונית.** כל מה שלא ברשימה הגלובלית = "שלח לבדיקה", כולל CDN-ים של אתרים מותרים (fonts, cloudfront, akamai…). בלי רשימה התחלתית טובה – אתרים מותרים ייראו שבורים.
6. **אכיפה.** פרוקסי שמוגדר במכשיר ניתן להסרה בשתי לחיצות. צריך אחד מאלה: שותפות עם ספק אינטרנט (כמו נטפרי), VPN/פרופיל נעול ב-MDM, או ראוטר. בלי זה זה "מסנן מרצון".
7. **OTP.** שליחת SMS/מייל היא mock (הקוד נכתב ללוג). לחבר ספק אמיתי – או לא לחשוף את כניסת ה-OTP.

## 3. חשוב – בחודש הראשון אחרי העלייה

- **תור בדיקה אנושית.** תמונות שה-VLM לא בטוח בהן (P(Yes) בין ~0.05 לסף) ותמונות ב-`error` אחרי 3 ניסיונות → מסך מנהל "אשר/חסום". כך עובדת גם נטפרי (AI + בודקים).
- **בדיקת סרטון בודד** (כמו נטפרי: סרטון נחתך לפריימים, נבדק, ונפתח לכולם):
  הורדה → `ffmpeg` (1 פריים לשנייה + החלפות סצנה) → איחוד פריימים כמעט זהים → VLM לכל פריים (עצירה ב"כן" הראשון) → פסיקה לפי מזהה הסרטון → פתיחה ברשימה.
  עלות משוערת: סרטון של 10 דקות ≈ 100–200 פריימים אחרי איחוד ≈ 2–4 סנט.
- **CSP של אתרים** חוסם את הסקריפטים המוזרקים (סרגל, רענון תמונות) באתרים מחמירים. לשלב nonce בכותרת ה-CSP.
- **תמונות בתוך JSON/JS (base64) וב-WebSocket** – עדיין לא נבדקות (למשל תמונות ממוזערות בחיפוש תמונות).
- **קנה מידה:** כמה תהליכי `mitmdump` מאחורי load balancer (TCP), Postgres במקום SQLite כשיש יותר משרת אחד, Redis לתור התמונות (התור היום בזיכרון; אחרי הפעלה מחדש תמונות ממתינות נשלחות שוב אוטומטית אחרי 5 דקות).
- **מסנן מלל:** 35 מילים בעברית / 53 באנגלית, בלי הקשר. להרחיב, או לעבור למסווג טקסט קטן.
- **אודיו** (קול אישה בשירים) – לא מטופל בכלל.
- **אנדרואיד:** אפליקציות לא סומכות על תעודת CA שהמשתמש התקין – הן לא יעבדו דרך הפרוקסי (פתרון: MDM / רשימת passthrough).

## 4. המודל – מה נבדק ומה ההמלצה

### האם חייבים VLM?

**כן – להכרעה. לא – לכל תמונה ברזולוציה מלאה במודל גדול.**

- ההכרעה דורשת הבנה (לבוש, הקשר של רחצה, ציור מול צילום, הערכת גיל). מסווג אובייקטים פשוט לא מספיק, ו-VLM מתאים.
- מודלים חדשים כבר טובים בפרטים קטנים (ראו V* למטה). זה בדיוק "אישה קטנה ברקע".
- **אבל רזולוציה עולה כסף:** מודלי Qwen מקודדים בערך 32×32 פיקסלים לכל טוקן. 1280×960 ≈ 1,200 טוקנים; תמונת 4K ≈ 8,000 (פי 6–7 בעלות). לתמונות ענק עדיף חיתוך לאריחים מאשר להגדיל את הרזולוציה לכל התמונות.
- **תמונה מטושטשת:** VLM לא "רואה" יותר ממה שיש בפיקסלים. כאן עובד כלל "לא בטוח = חסום", לא מודל גדול יותר.

### מועמדים (נכון לאוקטובר 2026)

| מודל | גודל | רישיון | V* (פרטים קטנים) | תפקיד מוצע |

### צינור מומלץ

1. **מטמון** לפי תוכן (קיים; כמו נטפרי – "אותו תוכן דיגיטלי לא נבדק שוב").
2. **שלב 1 – Qwen3.5-2B/4B אחרי fine-tune (LoRA)**, ברזולוציה בינונית: "יש בכלל דמות אנושית/מצוירת?". "בטוח שאין" → מותר. כך עוברות רוב התמונות (מוצרים, אייקונים, באנרים).
3. **שלב 2 – Qwen3.5-9B** ברזולוציה גבוהה עם ה-prompt והסף הא-סימטרי (מה שמומש עכשיו).
4. **שלב 3 – בודק אנושי** למה שלא בטוח.
5. **אימון:** מורה גדול + אדם מתייגים מתעבורה אמיתית → fine-tune ל-9B ול-2B **לפי התקן שלך**. אחרי זה, וגם אחרי כל שינוי prompt – מריצים שוב את סט הזהב.

### איך למדוד בעצמך (במקום להאמין להערכות)

```bash
vllm serve Qwen/Qwen3.5-9B --port 8001
IMAGE_ANALYZER=openai VLM_API_BASE=http://127.0.0.1:8001/v1 python -m tools.eval_golden_set golden/     # דיוק
VLM_API_BASE=http://127.0.0.1:8001/v1 GPU_PRICE_PER_HOUR=0.8 python -m tools.benchmark_vlm golden/ 32    # תפוקה ועלות ל-1,000
```

ומהתעבורה: כמה בקשות תמונה למשתמש ביום, כמה מהן חדשות אחרי המטמון, וכמה מכילות בני אדם. עם שלושת המספרים האלה מחשבים את העלות לחודש.

## 5. מה נטפרי עושה (לצורך השוואה)

- **התקן:** "כל תמונה של אישה נחסמת, גם אם צנועה"; ילדות עד גיל 9 – אם לא בלבוש צנוע; עד גיל 3 – אם לא לבושות. **זה בדיוק התקן שב-prompt של הפרויקט.**
- **מטמון:** סטטוס התמונה לפי התוכן הדיגיטלי, לא לפי הכתובת. שינוי גודל = תמונה חדשה. זמן בדיקה: "בין כמה שניות לכמה דקות". קרוב ל-4 מיליארד תמונות נבדקו (תחילת תשפ"ו).
- **תצוגה:** תמונה חסומה מוצגת מפוקסלת 4×4 או עם 🚫 (דומה לפרויקט: 3×3 / 5×5).
- **וידאו:** סרטון נשלח לבדיקה מכפתור בנגן (יוטיוב, וימאו, וויסטיה), נחתך לפריימים, נבדק, ונפתח לכל המשתמשים. סרטון שנפסל מציג "הוידאו נחסם".
- **עסקי:** 15 ₪ לקו לחודש, 47 עובדים, הכנסה כ-10 מיליון ₪ (2023), עמותה.
